# 인더포레스트 지원용 — Modbus TCP 접근통제 진단

상태: 기술 검토 반영 초안. IP 직접 차단·조치 후 패킷 재검증은 미완료.

## 프로젝트와 지원 직무

보안관제 경험을 바탕으로, OpenPLC·FUXA 가상 제어환경의 정상 Modbus 패킷을 분석하고 일반 client의 무자격 운전 명령 변경을 재현한 개인 실습이다. 첨부 채용공고의 OT 진단·연구 결과 보고 업무와 연결한다. 직접 구축한 환경으로 블랙박스 진단, 신규 CVE, 실제 산업설비 진단, 표준 적합성 평가를 주장하지 않는다.

## 문제와 수행 결과

| 단계 | 확인한 사실 | 근거 |
|---|---|---|
| 정상 기준선 | 정지 27쌍, 운전 120쌍의 요청·응답 | [정지 분석](../evidence/baseline/fuxa-openplc-pcap-2026-09-18.md), [운전 분석](../evidence/baseline/fuxa-openplc-operation-2026-09-18.md) |
| 명령과 영향 | FC05 Coil 0 ON/OFF, Coil 00→03→00, 수위 0→6→0 | 운전 PCAP과 PLC 원본 |
| 접근통제 평가 | 별도 client가 자격증명 없이 명령 변경; 수위 0→3, OFF 복원 | [평가 기록](../evidence/assessment/ac-02-unauthenticated-write-2026-09-19.md) |
| 개선 | 평가자를 assessment로 분리 | [구성](../lab/compose/compose.yaml) |
| 재검증 한계 | DNS 실패 확인; IP 직접 차단 미검증, HMI 정상 동작은 운영자 보고 | [재검증 기록](../evidence/retest/ac-01-network-separation-2026-09-19.md) |

## 증명하는 역량

- 정상 통신을 기준으로 기능코드·wire offset·상태값을 해석한다.
- 요청 성공 응답과 실제 모델 상태 변화를 구별해 확인한다.
- 프로토콜 특성, 배치의 접근통제 문제, 제품 취약점 주장을 구분한다.
- 원본 로그와 PCAP을 연결하고, 증거가 부족한 판정을 부분 완료로 남긴다.
- 제한된 쓰기와 OFF 복원 시도를 사용하고 복원 실패 가능성을 명시한다.

## 면접 설명

1. 정상 기준선: 쓰기 자체는 정상 HMI에서도 발생하므로 출발 역할과 정책을 함께 봐야 한다.
2. 발견사항: 같은 제어망의 일반 client가 운전 명령을 변경할 수 있었다. 네트워크 접근은 선행 조건이다.
3. 개선: 평가자 연결을 분리했다. FUXA 침해 또는 신뢰망에 연결된 client까지 막는 통제는 아니다.
4. 검증의 수정: DNS 오류만으로 IP 차단을 확정할 수 없어 재검증 판정을 낮추고 대조 시험을 설계했다.
5. 남은 일: 실행 버전 식별, IP 직접 접근 시험, 조치 후 HMI PCAP과 복원 확인이다.

## 현재 증거에 맞는 이력서 문장

OpenPLC·FUXA 가상 환경에서 Modbus TCP 정상 패킷과 공정 상태를 분석하고, 공유 제어망의 비인가 역할에서 운전 명령 변경을 재현했습니다. 평가자 네트워크 분리와 재검증을 수행하며 DNS 실패와 네트워크 차단의 증거 범위를 구분해 진단 보고서를 작성했습니다.

## 본인 기여와 제출 전 확인

실제 수행한 구성·시험·분석 항목, 도구/AI 도움을 받은 범위, 직접 설명 가능한 코드를 지원자가 확인해 기재한다. 저장소만으로 독립 수행 범위를 추정하지 않는다. 경력 연수 외 개인 이력·자격을 임의로 추가하지 않는다.
